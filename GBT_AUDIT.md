# Аудит и улучшения ветки GBT

База: `catalog-crm` (`968c4fc`). Проверены портал WK CRM, отчётные разделы,
каталог LinkOne и 15 статических витрин `data/`.

## Найдено и исправлено

1. Переходы LinkOne `K…` не находили страницы `DK…`.
2. Не учитывались ссылки `1-K…` и варианты номеров с суффиксом `A`.
3. Глобальный поиск фактически работал только по прайсу.
4. Каталог не искал по новому артикулу, ЕКМТР, китайскому названию, ТНВЭД и узлу.
5. Номера нормализовались только по дефисам.
6. CSV допускал формулы Excel из значений `=`, `+`, `-`, `@`.
7. Таблицы скрывали строки сверх лимита без раскрытия.
8. Сортировка смешанных типов была нестабильной.
9. График делил на ноль при одном периоде или нулевом диапазоне.
10. Полнотекстовый поиск мог показать ответ предыдущего запроса.
11. Поиск LinkOne прекращался после 401 совпадения.
12. Корзина не проверяла структуру данных из `localStorage`.
13. Итог корзины не обновлялся после изменения количества.
14. Диалог детали не управлял фокусом.
15. Тема не сохранялась и принудительно была тёмной.
16. Вкладки не имели прямых URL и истории Back/Forward.
17. Фильтры каталога терялись при навигации.
18. На мобильном экране скрывался основной поиск.
19. Интерфейс ошибочно утверждал, что загрузка остатков пересчитывает обеспеченность.
20. Не обрабатывалась ошибка загрузки изображения LinkOne.
21. Интерактивные строки и дерево были недоступны с клавиатуры.
22. Заголовки таблиц не сообщали направление сортировки.

## Аудит остатков и распределения по плановым заказам

Дата снимка: **14.09.2026**. Проверено 775 позиций WK и 8 103 строки
плановой потребности.

| Контроль | Результат |
|---|---:|
| Баланс количества | 41 372 = 22 228 склад + 3 863 закупка к сроку + 170 опоздание + 841 просрочено/без срока + 14 270 дефицит |
| Баланс стоимости | 4 577,54 млн ₽ распределены без материального расхождения округления |
| Превышение доступного остатка | 0 позиций |
| Превышение объёма открытой закупки | 0 позиций |
| Построчный дисбаланс количества | 0 позиций |
| Просроченные открытые приходы | **1 310 ед. по 133 кодам** |

Обнаружена методологическая ошибка: открытая закупка с плановым месяцем
раньше даты снимка могла попадать в корзину «закупка успевает». Функция
`allocate()` исправлена: такой приход считается просроченным с ненадёжной
датой и относится в корзину `undated`, пока срок не будет подтверждён.
Добавлен регрессионный тест.

`data/provision.json` пересобран из актуального репозитория `TOPO`. После
исправления подтверждённая закупка к сроку уменьшилась с 599,04 до
**446,92 млн ₽**, 73,51 млн ₽ выделено в проблемную корзину, а непокрытый
дефицит вырос до **1 607,75 млн ₽**. Обеспеченность к сроку теперь
составляет **62,2%**, а не 65,5%.
